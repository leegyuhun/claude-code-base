개발 흐름도

/prd {이슈ID} 한 줄로 시작해서 PR/MR까지. 에이전트가 PHASE를 따라 진행하고, 훅이 사이사이에서 검사하고, 사람은 세 곳에서만 멈춘다.

에이전트 / 커맨드 훅이 자동 검사 사람이 멈춰서는 곳 루프 중단

2. 사이사이에서 도는 것 — 훅 층

위 PHASE 흐름은 사람이 명령을 넣어 진행시키고, 아래 훅은 그 사이에서 자동으로 검사한다. 전부 .claude/settings.json에 팀 공유로 배선돼 있다.

PreToolUseBash 실행 직전
위험 명령 차단master/Release push(refspec 포함) · force push(-f, +브랜치) · reset --hard · cd && 체이닝 · 브랜치 명명 규칙 위반.
PostToolUse도구 실행 직후 · 짧은 루프
fast_check 실패 → 즉시 고치라고 요구git status로 source_globs에 걸리는 변경을 보고, 있으면 harness.json의 fast_check.cmd(린트·타입체크)를 돌린다. 명령이 비어 있으면 아무것도 하지 않는다.
Stop턴 종료 시 · 긴 루프
하네스 무결성 + PHASE 6 빌드 / PHASE 7 검증계약실패하면 exit 2로 종료를 막고 stderr에 "무엇이 왜 실패했고 다음에 어디를 볼지"를 쓴다. 그 텍스트가 다음 턴의 지시가 된다. 빌드 명령이 없으면 실패가 아니라 "검증기 부재"로 통과.
PreCompact컴팩션 직전
작업 좌표 보존ACTIVE_ISSUE·PHASE·스프린트와 STATUS.md/GOAL.md/attempts.log 경로만 남긴다. 내용을 뱉으면 컴팩션 목적을 스스로 무너뜨린다.

3. 실패하면 어떻게 다시 도는가

재시도 횟수는 모델이 세지 않는다. workspace/#207500/.loop/counter.json에 scope별로 기록되고, 세션이 끊기거나 컴팩션이 일어나도 유지된다.

같은 scope 3회build · feedback · manual · review:N 각각 독립. 빌드가 상한에 걸려도 리뷰 카운터는 무관.

중단되면  STATUS.md에 LOOP=halted와 사유가 기록되고 PHASE는 그대로 둔다. /next가 PHASE 안내보다 먼저 중단 사유와 최근 시도(.loop/attempts.log)를 보여준다. 접근을 바꾼 뒤 python .claude/scripts/loop_state.py clear-halt로 재개.

4. 사람이 멈춰서는 곳

15개였던 [PAUSE] 중 "산출물을 보지 않아도 정할 수 있는 것"은 /prd 첫 인터뷰로 옮겼다. 산출물을 봐야 알 수 있거나 되돌릴 수 없는 것만 남았다.

첫 이슈3곳

  • 작업 정책 인터뷰 — /prd Phase 0.5, 프로젝트당 1회
  • PHASE 8 수동 UI 테스트
  • PHASE 9 PR/MR 머지 확인

다음 이슈부터2곳

  • PHASE 8 수동 UI 테스트
  • PHASE 9 PR/MR 머지 확인

둘 다 앞당길 수 있는 성질이 아니다 — 구현이 끝나야 테스트할 수 있고, PR/MR은 외부 시스템 상태다.

예외일 때만

  • 트랙 판정이 애매 (Defect 조건 3~4개)
  • AUTO_RUN 미충족 — 공용 모듈·DB 스키마·신규 모듈·반려 재진입
  • subagent BLOCKED
  • 요구사항 변경 감지
  • 루프 중단 (halt)

5. 막혔을 때

/next

STATUS.md를 읽고 지금 실행할 명령어를 알려준다. 루프가 중단됐으면 그 사유부터.

/status

현재 이슈·PHASE·스프린트·브랜치 불일치 여부를 한눈에.

python .claude/scripts/loop_state.py status

scope별 시도 횟수와 최근 실패 이력.

python .claude/scripts/loop_state.py clear-halt

중단 해제. 같은 방법으로 재시도하면 같은 결과가 나오니 접근을 바꾼 뒤에.

/rollback {PHASE}

자동 진행된 결정(plan 검토, 트랙 판정)이 마음에 안 들면 되돌린다.

python .claude/scripts/policy.py set plan_review=pause

정책 변경. 키: branch · track_confirm · plan_review · auto_run · pitfall_capture

이 페이지는 다음 문서를 요약한 것이다. 세부 절차는 원문을 따른다.

  • docs/프로세스.md — 전체 흐름과 단계별 명령어
  • docs/구조.md — 파일 구조와 훅 배치
  • .claude/harness.json — 빌드·테스트·fast_check 명령 어댑터
  • .claude/agents/*.md, .claude/commands/*.md — 각 PHASE의 실제 절차

알려진 한계: 빌드 게이트(층 B)는 harness.json 명령 품질에 달려 있다. 대상 레포에 적용해 첫 스프린트를 돌린 뒤에야 확인된다.
