  그림으로 보려면: docs/흐름도.html 을 브라우저로 연다 (같은 내용을 레일 다이어그램으로)

전체 흐름 한눈에

  /prd {이슈ID}
      ↓ PRD.md 생성 + 브랜치 생성
  Orchestrator  →  plan.md  →  ROADMAP.md  →  CLAUDE.md
      ↓
  Planner  →  GOAL.md
      ↓
  /sprint-dev  →  소스 구현
      ↓
  Validator  →  빌드/테스트  →  수동테스트  →  commit + push + PR/MR 초안 안내

  ┌───────┬───────────────────┬────────────────────────────────┬──────────────────────────────────────┐
  │ PHASE │ 에이전트/커맨드   │ 프롬프트                       │ 산출물                               │
  ├───────┼───────────────────┼────────────────────────────────┼──────────────────────────────────────┤
  │ PRD   │ /prd              │ /prd #207500                   │ PRD_#207500.md, 브랜치               │
  │ 1~4.5 │ Orchestrator      │ (아래 참조)                    │ plan.md, ROADMAP.md, CLAUDE.md       │
  │ 5     │ Planner           │ (아래 참조)                    │ sprints/sprint-01/GOAL.md            │
  │ 6     │ /sprint-dev       │ /sprint-dev                    │ 코드 구현, 스프린트 브랜치           │
  │ 7~10  │ Validator         │ (아래 참조)                    │ DONE.md, commit, push, PR/MR 초안    │
  └───────┴───────────────────┴────────────────────────────────┴──────────────────────────────────────┘

  막히면: /next 입력 → 현재 PHASE 기반 실행 명령어 자동 안내

루프 층 (위 흐름 위에 얹혀 자동으로 도는 것)

  위 PHASE 흐름은 사람이 명령어를 넣어 진행시킨다.
  루프 층은 그 사이사이에서 자동으로 검사하고, 실패하면 되돌린다.

  ┌──────────────┬──────────────────┬────────────────────────────────────────────┐
  │ 시점         │ 훅               │ 하는 일                                    │
  ├──────────────┼──────────────────┼────────────────────────────────────────────┤
  │ 셸 실행 전   │ PreToolUse       │ 위험 명령 차단 (Bash·PowerShell 공통)      │
  │ 도구 실행 후 │ PostToolUse      │ 소스 변경 시 fast_check 실행 → 실패 시     │
  │              │ (짧은 루프)      │ 즉시 교정 요구 (harness.json)              │
  │ 턴 종료 시   │ Stop             │ 하네스 무결성 + PHASE 7 검증계약           │
  │              │ (긴 루프)        │ (PHASE 6 빌드 게이트는 기본 꺼짐 —         │
  │              │                  │  HARNESS_STOP_BUILD_GATE=1 로 켬)          │
  │              │                  │ 실패하면 종료를 막고 무엇을 볼지 알려줌    │
  │ 컴팩션 직전  │ PreCompact       │ 작업 좌표 보존 (경로만, 내용 아님)         │
  └──────────────┴──────────────────┴────────────────────────────────────────────┘

  재시도 횟수는 모델이 세지 않는다. workspace/{이슈}/.loop/counter.json 에 기록되며
  세션이 끊기거나 컴팩션이 일어나도 유지된다.

  멈추는 조건 (셋 중 하나라도 걸리면 중단):
    - 같은 실패가 2회 연속        ← 상한보다 먼저 걸린다
    - 같은 작업 3회 시도
    - 30분 경과

  멈추면 STATUS.md에 LOOP=halted 가 기록되고, PHASE는 그대로 둔다.
  /next 가 중단 사유와 최근 시도 이력(.loop/attempts.log)을 먼저 보여준다.

    재개:     python .claude/scripts/loop_state.py clear-halt
    상태확인: python .claude/scripts/loop_state.py status

  ※ PHASE 8(수동 UI 테스트)은 루프가 절대 막지 않는다. 사람이 직접 확인해야 하는
    단계이므로 여기서 막으면 빠져나갈 방법이 없다.
  ※ 빌드 명령이 없으면(.claude/harness.json의 cmd 비어 있음) 실패가 아니라 "검증기 부재"로
    처리하고 통과시킨다. 없는 걸 실패로 세면 루프가 영원히 헛돈다.

사람이 멈춰서는 지점

  판단 기준을 미리 정할 수 있는 것은 /prd 최초 1회 인터뷰(Phase 0.5)로 옮겼다.
  산출물을 봐야 알 수 있는 것과 되돌릴 수 없는 것만 남겼다.

  [첫 이슈]
    1. 작업 정책 인터뷰    /prd Phase 0.5 — 이 프로젝트에서 딱 한 번
    2. plan.md 승인        PHASE 3 — 기본 pause (선 계획 후 실행). notify 정책이면 요약만 보고 진행
    3. 수동 UI 테스트      PHASE 8 — 런타임 검증이 0%이므로 유일한 안전망
    4. push 확인           PHASE 9 — 로컬 커밋은 묻지 않고, 원격 작업만 한 번 확인
    5. PR/MR 머지 확인     PHASE 9 — 외부 시스템 상태

  [다음 이슈부터]
    2~5 만. (Defect 트랙은 2 없음)

  선택형 질문은 번호를 붙인다 — `(1. 예 / 2. 아니오)` 처럼 쓰고 번호·단어 어느 쪽 답도 받는다.

  [예외일 때만 추가로 뜬다]
    - 트랙 판정이 애매할 때      Defect 조건 5개 중 3~4개 충족
    - AUTO_RUN 조건 미충족       공용 모듈 수정 / DB 스키마 변경 / 신규 모듈 / 반려 재진입
    - BLOCKED                    subagent가 진행 불가를 보고
    - 요구사항 변경 감지
    - 루프 halt                  같은 실패 반복 또는 상한 도달
    - 빌드 실패 상한 도달

  정책 확인/변경:
    python .claude/scripts/policy.py show
    python .claude/scripts/policy.py set plan_review=notify

  되돌리기: 자동 진행된 결정이 마음에 안 들면 /rollback [옵션 번호]
  (plan.md 검토를 notify로 바꿔도 되는 것은 이 되돌리기가 가능하기 때문이다)

단계별 상세 (예시: 이슈 #207500, 현재 브랜치 main)

Step 1. PRD 생성  (/prd)

  /prd #207500

  → 이슈 본문 붙여넣기 [PAUSE] (이슈 트래커 연동 없음 — EXTRA_CONTEXT로 충분하면 생략)
  → 기술 분석 (변경 예상 파일, 공유 모듈 여부, DB 변경 여부)
  → 통합 확인 [PAUSE] 1회 — 보완 + 부족한 항목 GAP 질문 + 트랙 제안(정책상 확인 필요할 때만)
  → docs/PRD_#207500.md 생성
  → 브랜치 자동 결정 (질의 없음): main_#207500 생성 — ISSUE_BRANCH / PARENT_BRANCH를 STATUS.md에 기록
       현재 브랜치를 쓰려면 `/prd #207500 --here` (또는 정책 branch=current)
  → Sprint 트랙이면 Orchestrator로 바로 이어감

  산출물: docs/PRD_#207500.md, workspace/#207500/STATUS.md, 브랜치 main_#207500

---
Step 2. 계획 수립  (Orchestrator · PHASE 1~4.5)

  /prd 완료 후 Orchestrator 자동 시작 (또는 수동 실행):

  .claude/agents/orchestrator.md를 읽고 현재 PHASE부터 실행해줘.
  [PAUSE] 지점에서 멈추고 내 확인을 기다려. 코드 구현은 하지 마.

  PHASE 1 — PRD 검증
    → 필수 섹션 확인 (목적/기능/완료기준/제약조건)
    → 통과 시 PHASE 2 진행

  PHASE 2 — plan.md 생성
    → PRD 분석 → 기능 목록 (우선순위 P0/P1/P2, 복잡도 S/M/L)
    → plan.md 저장

  PHASE 3 — plan.md 검토 [PAUSE] (정책 plan_review — 기본 pause)
    → plan.md 내용 요약 출력
    → 수정 있으면 직접 편집 후 '계속' 입력 (notify 정책이면 요약만 보고 계속 — /rollback [1]로 되돌림)

  PHASE 4 — ROADMAP.md 생성
    → 스프린트 분할 (스프린트당 3~5일, P0 먼저)
    → sprints/ROADMAP.md 저장

  PHASE 4.5 — 프로젝트 초기화 + CLAUDE.md [조건부 PAUSE]
    → 프로젝트 파일·CLAUDE.md가 이미 있으면 질의 생략
    → 없을 때만: 초기화 여부 / CLAUDE.md 생성 방법 선택 (claude /init 권장)
    → 스택 감지 → .claude/harness.json 빌드/테스트/fast_check 명령 채움

  산출물: plan.md, sprints/ROADMAP.md, CLAUDE.md, .claude/harness.json

---
Step 3. 스프린트 계획  (Planner · PHASE 5)

  .claude/agents/planner.md를 읽고 현재 스프린트 GOAL.md를 작성해줘.
  코드 구현은 하지 마. GOAL.md 작성만 해.

  → ROADMAP.md 기반으로 현재 스프린트 분석
  → 이슈 상세 재조회 (필요 시)
  → sprints/sprint-01/GOAL.md 생성
       - 구현 기능 체크리스트 (예상 소요 시간 포함)
       - 검증 계약 (자동/수동 항목)
       - 예상 산출물 (생성/수정 파일 목록)
       - 수동 테스트 시나리오

  산출물: sprints/sprint-01/GOAL.md

---
Step 4. 구현  (/sprint-dev · PHASE 6)

  /sprint-dev

  → 브랜치 자동 생성: main_#207500_sprint-01 (항상 ISSUE_BRANCH에서 분기 — STATUS.md SPRINT_BRANCH 기록)
  → 구현 Plan 출력 (순서 + 접근 방식) [PAUSE]
  → '실행' 입력 → GOAL.md 체크리스트 순서대로 기능 구현
       ✅ 기능 1 구현 완료
       ✅ 기능 2 구현 완료
       ...
  → 최종 빌드 확인
  → PHASE 7로 전환

  브랜치: main_#207500_sprint-01
  커밋 없음 — Validator가 완료 시점에 한 번만 커밋

---
Step 5. 검증 + PR/MR 안내  (Validator · PHASE 7~10)

  .claude/agents/validator.md를 읽고
  workspace/#207500/sprints/sprint-01 검증을 시작해줘.
  [PAUSE] 지점에서 멈추고 내 확인을 기다려.

  PHASE 7 — 자동 검증
    → harness_config.py run build 실행 (실패 시 최대 3회 자동 수정)
    → harness_config.py run test 실행
    → GOAL.md 검증 계약 독립 채점 ([ ] → [x])
    → 코드 리뷰 스코어카드

  PHASE 8 — 수동 테스트 [PAUSE]
    → GOAL.md 수동 테스트 시나리오 출력
    → 애플리케이션 실행 후 직접 테스트
    → '통과' 또는 '수정 필요: {내용}' 입력

  PHASE 9 — 커밋 + push + PR/MR 안내
    → DONE.md 생성 (완료 기능, 변경 파일, 기술 부채) — 리뷰가 모두 끝난 뒤 1회만 작성
    → TECH_DEBT.md 업데이트
    → commit (commit-writer가 한국어 메시지 자동 작성, 이번 작업 파일만 선별 스테이징 — 묻지 않음)
    → [PAUSE] push 확인 — 원격 작업이라 여기서 한 번 묻는다
    → git push -u origin main_#207500_sprint-01
    → PR/MR 제목·본문 초안 출력 (타겟: ISSUE_BRANCH = main_#207500) — 호스팅 화면에서 직접 생성
    → [PAUSE] PR/MR 확인 후 '머지 완료' 입력

  PHASE 10 — 다음 스프린트 또는 완료
    → 스프린트가 더 있으면: CURRENT_SPRINT 업데이트 → PHASE 5로 (Step 3 반복)
    → 모든 스프린트 완료 시: 최종 PR/MR(main_#207500 → main) 안내 후 "MVP 달성!"

  산출물: DONE.md, commit, push, PR/MR 초안

브랜치 전략

  이슈ID 있을 때:

    main                              ← 현재 브랜치
      └── main_#207500                ← /prd 생성 (이슈 베이스)
            ├── main_#207500_sprint-01 ← /sprint-dev 생성 → PR/MR → main_#207500
            └── main_#207500_sprint-02 ← (다음 스프린트)   → PR/MR → main_#207500

  이슈ID 없을 때 (임시 ID 작업):

    main                              ← 이슈 브랜치 없음 — 현재 브랜치가 ISSUE_BRANCH
      └── main_sprint-01              ← /sprint-dev 생성 (Sprint 트랙일 때만)

  브랜치 정본은 STATUS.md의 PARENT_BRANCH · ISSUE_BRANCH · SPRINT_BRANCH 이다.
  Validator의 PR/MR 대상·diff 기준은 이 값으로 정한다 (브랜치명 재추론 없음).

유틸리티 커맨드

  /next          ← 지금 뭘 실행해야 하는지 명령어 자동 안내
  /status        ← 현재 PHASE, 스프린트, 에이전트 상태 한눈에
  /rollback [N]  ← 이전 PHASE로 되돌리기 (옵션 번호 직접 지정 가능)
  /sprint-log    ← 현재 스프린트 GOAL/DONE/OUT_OF_SCOPE 요약
  /debt          ← TODO 주석 + 기술 부채 종합 보고
  /branch        ← 브랜치 수동 생성

  루프 층 직접 조작 (보통은 훅이 알아서 한다):

    python .claude/scripts/loop_state.py status       ← 현재 카운터·중단 여부·최근 시도
    python .claude/scripts/loop_state.py clear-halt   ← 중단 해제 후 재개
    python .claude/scripts/loop_state.py reset --scope build   ← 특정 루프만 리셋
    python .claude/scripts/gate_harness.py            ← 하네스 무결성 수동 검사
    python .claude/tests/run_all.py                   ← 훅·스크립트 회귀 테스트 (수정 후 수동 실행)

  템플릿 재동기화: clone_claude_template.bat (설정: clone_claude_template.json) — 상세는 Readme.md

  MVP 완료 후 신규 요구사항이 생기면 Orchestrator PHASE 11 (Re-plan):

  .claude/agents/orchestrator.md를 읽고 PHASE 11을 실행해줘.
  [PAUSE] 지점에서 멈추고 내 확인을 기다려. 코드 구현은 하지 마.

  → PRD.md에 새 요구사항 추가 → plan.md + ROADMAP.md 갱신 → Step 3으로 재진입
