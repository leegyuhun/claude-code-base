# Codex 대형 프로젝트 개발 프로세스

## 상태 흐름

```
INTAKE → PLANNING → READY → IMPLEMENTING → REVIEWING → VALIDATING → HUMAN_GATE → DONE
                         ↑                 │              │
                         └── FEEDBACK ─────┴──────────────┘
```

`BLOCKED`와 `ESCALATED`는 모든 단계에서 진입할 수 있다. 상태와 다음 행동은 반드시 `workspace/{issue}/STATUS.md`에 기록한다.

## INTAKE

`00-INTAKE.md`로 Sprint 또는 Defect를 분류한다. 증상/목표, 범위, 영향 모듈, 공유 유닛, CP949, 데이터, SQL, 검증 필요 사항을 기록한다. 새 유닛·스키마·다중 모듈이 필요하면 Sprint다.

## PLANNING / READY

Sprint는 `GOAL.md`에 작은 구현 항목, 자동 검증, 수동 테스트, 비범위, 롤백 신호를 쓴다. 계획이 불명확하거나 공유 인터페이스 변경이 필요하면 `READY`로 넘어가지 않는다.

## IMPLEMENTING / REVIEWING

한 구현자는 한 GOAL 또는 FEEDBACK 항목만 맡는다. 가설·변경·명령·결과는 `PROGRESS.md`에 남기고 GOAL 완료 체크는 독립 검증 뒤에만 변경한다. reviewer는 구현자와 별도로 계약·diff를 읽고, Critical 또는 High가 있으면 `FEEDBACK.md`를 만들어 구현으로 되돌린다.

## VALIDATING / HUMAN_GATE

자동 검증 항목을 새로 실행한다. Delphi 변경은 가능한 경우 `build.bat debug`로 빌드하고 관련 테스트만 실행한다. 수동 임상 시나리오, DB 마이그레이션, 커밋·push, 배포, 외부 이슈 변경은 사람이 맡는다.

## 에스컬레이션

동일한 첫 오류가 두 번 반복, 전체 반복이 10회 초과, 공유 인터페이스·데이터 마이그레이션·권한 변경 필요, CP949 안전한 수정 방법 미확정 시 자동 반복을 멈춘다. 시도 이력, 가설, 증거, 필요한 결정을 보고한다.
