# Codex 개발 프로세스

## 1. 작업 계약 준비

제품 코드 작업은 `.codex/ACTIVE_ISSUE`와 PRD 또는 GOAL 문서로 식별한다. 요청에 범위와 검증 방법이 없으면 Codex는 이미 확인 가능한 범위부터 조사하고, 결과가 달라질 핵심 선택만 질문한다.

## 2. 계획과 구현

Codex는 `AGENTS.md`, `VISION.md`, 관련 작업 계약, 현재 diff를 읽는다. 비단순 작업은 `tasks/todo.md`에 다음을 남긴다.

- 수정할 파일과 목적
- 위험 요소: CP949, SQL, 공유 유닛, 데이터 보존
- 검증 명령과 기대 결과

구현은 범위를 넘지 않도록 최소 변경으로 수행한다. 공유 유닛의 기존 인터페이스 변경이나 외부 상태 변경이 필요하면 영향과 대안을 보고하고 멈춘다.

## 3. 검증과 사람 게이트

Codex는 변경 후 적합한 빌드·테스트·정적 검사를 새로 실행한다. Delphi 변경은 가능한 경우 해당 프로젝트의 `build.bat debug`로 검증한다. Critical 또는 High 문제가 남아 있으면 완료로 보고하지 않는다.

다음은 Codex가 자동 실행하지 않는다.

- 커밋과 push
- 배포
- DB 마이그레이션 실행
- 외부 이슈 트래커 상태 변경
- 광범위하거나 복구하기 어려운 삭제

사람은 검증 결과를 검토하고, 필요할 때 위 작업을 명시적으로 요청한다.
