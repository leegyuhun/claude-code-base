● Delphi 2007 Claude Code 개발 프로세스 (루프 엔지니어링)

핵심 원칙: "내가 프롬프트를 치는 게 아니라, 내가 설계한 루프가 에이전트를 프롬프팅한다."
계획과 검수는 사람이, 구현 ⇄ 검증 이터레이션은 루프(loop-sprint)가 자동 수행한다.
상세 설계: VISION.md(불변 방향), AGENTS.md(작업 규칙), .claude/loops/*/LOOP.md(5블록 설계)

---
전체 흐름 한눈에

  /prd #이슈번호
      ↓ PRD.md 생성 + 브랜치 생성 + Redmine InProgress
  Orchestrator  →  plan.md  →  ROADMAP.md  →  CLAUDE.md      (계획 — 사람 판단 PAUSE)
      ↓
  Planner  →  GOAL.md
      ↓
  /loop-sprint  →  [Maker 구현 ⇄ Checker 독립검증] 자동 반복      ← 구 PHASE 6↔7 인간 펌프 대체
      ↓             종료조건(기계검증) 충족까지
  (루프 종료 — 사람 게이트) 수동테스트  →  commit + push + GitLab MR
      ↓
  /resolve #이슈번호  →  Redmine Resolved

  ┌───────┬───────────────────┬────────────────────────────────┬──────────────────────────────────────┐
  │ PHASE │ 에이전트/커맨드   │ 프롬프트                       │ 산출물                               │
  ├───────┼───────────────────┼────────────────────────────────┼──────────────────────────────────────┤
  │ PRD   │ /prd              │ /prd #207500                   │ PRD_#207500.md, 브랜치, Redmine InProgress │
  │ 1~4.5 │ Orchestrator      │ (아래 참조)                    │ plan.md, ROADMAP.md, CLAUDE.md       │
  │ 5     │ Planner           │ (아래 참조)                    │ sprints/sprint-01/GOAL.md            │
  │ 6→7   │ /loop-sprint      │ /loop-sprint                   │ 코드 구현 + 자동검증, PROGRESS.md    │
  │ 8~10  │ 사람 게이트       │ (수동테스트 후 validator)      │ DONE.md, commit, push, GitLab MR     │
  │ 완료  │ /resolve          │ /resolve 207500                │ Redmine Resolved 100%                │
  └───────┴───────────────────┴────────────────────────────────┴──────────────────────────────────────┘

  막히면: /next 입력 → 현재 PHASE 기반 실행 명령어 자동 안내

메모리 3계층 (에이전트는 잊어도 repo는 잊지 않는다)

  VISION.md    ← 불변. 시스템이 향하는 방향, 절대 도메인 제약 (CP949·듀얼 DBMS·환자 안전). 루프 수정 금지
  AGENTS.md    ← 작업 규칙. Maker/Checker가 주입받는 인코딩·SQL·코딩·트랙·브랜치·리뷰 규칙
  PROGRESS.md  ← 가변. 루프가 매 이터레이션 갱신하는 시도/결과/다음계획 (workspace/{이슈}/)
  STATUS.md    ← 파이프라인 포인터 (PHASE/TRACK/스프린트). KEEP 커맨드 호환용 (workspace/{이슈}/)

---
단계별 상세 (예시: Redmine #207500, 현재 브랜치 main_delphi)

Step 1. PRD 생성  (/prd)

  /prd #207500

  → Redmine 이슈 자동 조회 (제목/설명/카테고리/우선순위)
  → 기술 분석 (변경 예상 파일, 공유 유닛 여부, DB 변경 여부)
  → 부족한 항목만 GAP 질문
  → docs/PRD_#207500.md 생성
  → [PAUSE] 브랜치 생성 여부 선택
       [1] main_delphi_#207500 브랜치 생성 (권장)
       [2] 현재 브랜치에서 작업
  → Redmine 상태 → InProgress
  → [PAUSE] Orchestrator 바로 시작할까요?

  산출물: docs/PRD_#207500.md, 브랜치 main_delphi_#207500

---
Step 2. 계획 수립  (Orchestrator · PHASE 1~4.5)

  /prd 완료 후 Orchestrator 자동 시작 (또는 수동 실행):

  .claude/agents/orchestrator.md와 workspace/{이슈}/STATUS.md를 읽고 현재 PHASE부터 실행해줘.
  [PAUSE] 지점에서 멈추고 내 확인을 기다려. 코드 구현은 하지 마.

  PHASE 1 — PRD 검증
    → 필수 섹션 확인 (목적/기능/완료기준/제약조건)
    → 통과 시 PHASE 2 진행

  PHASE 2 — plan.md 생성
    → PRD 분석 → 기능 목록 (우선순위 P0/P1/P2, 복잡도 S/M/L)
    → plan.md 저장

  PHASE 3 — plan.md 검토 [PAUSE]
    → plan.md 내용 요약 출력
    → 수정 있으면 직접 편집 후 '계속' 입력

  PHASE 4 — ROADMAP.md 생성
    → 스프린트 분할 (스프린트당 3~5일, P0 먼저)
    → sprints/ROADMAP.md 저장

  PHASE 4.5 — 프로젝트 초기화 + CLAUDE.md [PAUSE]
    → 프로젝트 이미 초기화됐나요? → '예'
    → CLAUDE.md 생성 방법 선택 (claude /init 권장)

  산출물: plan.md, sprints/ROADMAP.md, CLAUDE.md

  ※ Defect 트랙은 Orchestrator·Planner를 스킵하고 PRD `## 검증 계약`이 GOAL.md를 대체한다.
    → Step 1 다음 바로 Step 4(루프)로.

---
Step 3. 스프린트 계획  (Planner · PHASE 5)

  .claude/agents/planner.md와 workspace/{이슈}/STATUS.md를 읽고 현재 스프린트 GOAL.md를 작성해줘.
  코드 구현은 하지 마. GOAL.md 작성만 해.

  → ROADMAP.md 기반으로 현재 스프린트 분석
  → 이슈 상세 재조회 (필요 시)
  → sprints/sprint-01/GOAL.md 생성
       - 구현 기능 체크리스트 (예상 소요 시간 포함)
       - 검증 계약 (자동/수동 항목)  ← 루프 종료조건의 기준
       - 예상 산출물 (생성/수정 파일 목록)
       - 수동 테스트 시나리오

  산출물: sprints/sprint-01/GOAL.md

---
Step 4. 구현 루프  (/loop-sprint · PHASE 6→7 자동 반복)

  /loop-sprint

  → 브랜치 자동 생성: main_delphi_#207500_sprint-01
  → PROGRESS.md 생성 (루프 이터레이션 상태)
  → 이터레이션 자동 반복 (사람이 매 단계를 프롬프팅하지 않음):
       Maker(implementer) 항목 구현
         ⇄ Checker(Spec 리뷰 · 코드품질 리뷰 · 통합 게이트) 독립 검증
       종료조건 충족까지:
         · 빌드 build.bat debug 0 에러
         · DUnit 테스트 통과 (있을 때)
         · GOAL.md 검증계약 ✅자동 항목 100% (Checker가 코드 직접 읽어 채점)
         · 코드 리뷰 Critical 0 · High 0
  → 안전장치: 최대 10회 / 동일 에러 2연속 중단(공회전 방지) / 매 이터레이션 PROGRESS.md 기록
  → 파괴적 작업(push·삭제·마이그레이션) 루프 내 자동 실행 금지
  → 종료조건 충족 시 루프 종료 → Step 5 사람 게이트로

  빌드만 따로 복구할 땐: /loop-build-fix  (build.bat debug exit 0까지 근본원인 기반 수정)

  브랜치: main_delphi_#207500_sprint-01
  커밋 없음 — 사람 게이트 통과 후 한 번만 커밋

---
Step 5. 검증 마무리 + MR 생성  (사람 게이트 · PHASE 8~10)

  loop-sprint가 자동 검증(구 PHASE 7 — 빌드/테스트/검증계약/코드리뷰)까지 끝낸 상태.
  남은 것은 사람이 트리거한다. validator.md가 이 게이트를 담당한다:

  .claude/agents/validator.md와 workspace/{이슈}/STATUS.md를 읽고
  sprints/sprint-01 검증을 시작해줘.
  [PAUSE] 지점에서 멈추고 내 확인을 기다려.

  PHASE 8 — 수동 테스트 [PAUSE]
    → GOAL.md 수동 테스트 시나리오 출력
    → C:\YsrOutput\Exe\ EXE 실행 후 직접 테스트
    → '통과' 또는 '수정 필요: {내용}' 입력
       (수정 필요 시 → FEEDBACK.md 작성 후 /loop-sprint 재진입)

  PHASE 9 — 커밋 + push + GitLab MR 생성
    → DONE.md 생성 (완료 기능, 변경 파일, 기술 부채)
    → CHANGELOG.md 업데이트
    → TECH_DEBT.md 업데이트
    → commit (commit-writer가 한국어 메시지 자동 작성)
    → git push -u origin main_delphi_#207500_sprint-01
    → GitLab MR 자동 생성 (타겟: main_delphi_#207500)
         glab mr create (설치 시) → GitLab API → 수동 안내 폴백
    → [PAUSE] MR 확인 후 '머지 완료' 입력

  PHASE 10 — 다음 스프린트 또는 완료
    → 스프린트가 더 있으면: CURRENT_SPRINT 업데이트 → PHASE 5로 (Step 3 반복)
    → 모든 스프린트 완료 시: "MVP 달성!" 안내

  산출물: DONE.md, CHANGELOG.md, commit, push, GitLab MR

---
Step 6. Redmine 완료 처리  (/resolve)

  /resolve 207500

  → 작업 기간 자동 계산 (첫 커밋일 ~ 오늘)
  → [PAUSE] 확인 + 코멘트 입력 (선택)
  → Redmine 상태 → Resolved, done_ratio=100%

유틸리티 커맨드

  /loop-sprint    ← 구현 ⇄ 검증 루프 시작 (자동 반복)
  /loop-build-fix ← 빌드 복구 루프 (build.bat debug exit 0까지)
  /next           ← 지금 뭘 실행해야 하는지 명령어 자동 안내
  /status         ← 현재 PHASE, 스프린트, 에이전트 상태 한눈에
  /rollback       ← 이전 PHASE로 되돌리기
  /sprint-log     ← 현재 스프린트 GOAL/DONE/OUT_OF_SCOPE 요약
  /debt           ← TODO 주석 + 기술 부채 종합 보고
  /branch         ← 브랜치 수동 생성
