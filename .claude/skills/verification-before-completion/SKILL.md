# Verification Before Completion

## 핵심 원칙

검증 없는 완료 선언은 효율이 아니라 거짓말이다.

**증거가 먼저, 주장은 나중.**

이 규칙의 문자를 어기면 정신도 어기는 것이다.

## 절대 법칙

```
신선한 검증 증거 없이는 어떤 완료 상태도 주장할 수 없다.
```

지금 이 메시지에서 검증 명령을 실행하지 않았다면 통과를 주장할 수 없다.

## 게이트 함수

```
완료·성공 주장 전 반드시:

1. 식별: 이 주장을 증명하는 명령은 무엇인가?
2. 실행: 전체 명령을 새로 실행한다 (캐시·이전 결과 금지)
3. 읽기: 전체 출력 확인, 종료 코드 확인, 오류 건수 세기
4. 검증: 출력이 주장을 확인하는가?
   - 아니오: 증거와 함께 실제 상태를 말한다
   - 예: 증거와 함께 주장한다
5. 그 이후에만: 주장한다

어느 단계도 건너뛰는 것 = 검증이 아닌 거짓말
```

## YSR 프로젝트 검증 명령

### 컴파일 확인 (기능 완료 선언 전 필수)
```
set DPROJ={변경된 .pas가 속한 .dproj 경로} && build.bat debug
```
- .dproj 탐색: 변경된 .pas 파일이 속한 디렉토리에서 상위로 거슬러 올라가며 최초 발견 .dproj 사용
- 성공 기준: 종료 코드 0, "Build succeeded" 출력
- 실패 시: systematic-debugging 스킬 적용 (가설 수립 → 격리 → 수정)

### 주장 유형별 필요 증거

| 주장 | 필요 증거 | 불충분한 것 |
|------|-----------|-------------|
| 기능 구현 완료 | `build.bat debug` 출력: 에러 0건 | "코드가 맞아 보인다" |
| 버그 수정 완료 | 컴파일 성공 + 재현 경로 확인 | 코드 변경만 |
| 빌드 성공 | build.bat 실제 출력 | "문법이 맞다", "린터 통과" |
| 요구사항 충족 | GOAL.md 항목별 체크 + 컴파일 | 테스트 일부 통과 |
| 검증 계약 통과 | 각 항목 독립 실행 후 결과 | "전체적으로 맞다" |

## 경보 신호 — 즉시 중단

- "~할 것 같습니다", "아마 동작할 것 같습니다", "보기엔 맞습니다"
- 검증 전 "완료", "성공", "통과", "✅" 출력
- 커밋·PR 전 검증 미실행
- 이전 빌드 결과 재사용
- 부분 검증으로 전체 통과 추론

## 합리화 방지

| 핑계 | 현실 |
|------|------|
| "지금은 동작할 것" | build.bat을 실행해라 |
| "자신 있다" | 자신감 ≠ 증거 |
| "단 한 번만" | 예외 없음 |
| "린터가 통과했다" | 린터 ≠ 컴파일러 |
| "에이전트가 성공이라 했다" | 독립적으로 검증해라 |
| "피곤하다" | 피로 ≠ 면제 |
| "부분 확인으로 충분하다" | 부분은 아무것도 증명하지 않는다 |

## 언제 적용하는가

**항상 적용:**
- 기능 완료 선언 직전
- 버그 수정 완료 선언 직전
- Validator로 넘기기 직전
- 커밋 전 (Validator 담당이지만, implementer 사전 체크도 의무)
- 다음 기능으로 넘어가기 전

**이 규칙은 다음에도 적용:**
- 정확한 문구뿐 아니라 의역·유의어에도
- 성공을 암시하는 모든 표현
- "완료됐습니다 — 다음은..." 형식의 모든 전환 문구

## 핵심 요약

**검증 명령을 실행해라. 출력을 읽어라. 그 다음에 주장해라.**

예외 없음.
