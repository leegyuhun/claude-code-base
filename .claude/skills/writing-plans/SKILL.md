# Writing Plans (YSR)

## 핵심 원칙

계획 문서를 작성할 때 **컨텍스트 없는 엔지니어**를 독자로 가정한다.
도구·도메인·코드베이스에 대해 아무것도 모르는 숙련된 Delphi 개발자가
이 문서 하나만 보고 대화 없이 구현할 수 있어야 한다.

---

## 파일 구조 — 먼저 맵핑

구현 시작 전에 어떤 파일이 생성/수정되는지 명확히 나열한다.

- 정확한 경로 (예: `FwChart\Forms\TreatForm.pas`, `FwBohum\BL\BohumBL.pas`)
- 새 파일 vs 기존 파일 수정 구분
- 폼은 `.pas` + `.dfm` 쌍으로 나열

---

## 작업 단위 세분화

각 GOAL.md 기능 항목은 독립적으로 검증 가능해야 한다:

- 빌드 확인 가능
- 기능이 동작하는지 수동 확인 가능
- "기능 A 후 기능 B 가능"처럼 선행 순서가 필요하면 명시

---

## 금지 표현 (No Placeholders)

아래 표현이 있으면 계획이 미완성:

- "TBD", "TODO", "나중에 구현"
- "적절한 에러 처리 추가"
- "기능 X와 유사하게"
- "파일 경로는 추후 확인"
- 코드 예시 없이 "이렇게 구현" (어떻게인지 보여야 함)

---

## YSR 계획 문서별 필수 포함 항목

### GOAL.md
- 수정/신규 파일 목록 (정확한 경로)
- 공용 유틸 참조 명시 (MUtil.pas, MCOMFunction.pas, TtsQuery 등)
- CP949 주의사항 (Write 금지, Edit 한글 줄 우회)
- 검증 계약 (측정 가능한 기준)
- 수동 테스트 시나리오 (PHASE 8용)

> 양식: `.claude/templates/goal-format.md`

### plan.md
- 모든 PRD 요구사항이 기능 행에 포함
- P0/P1/P2 우선순위 명확
- 의존성 관계 명시

### ROADMAP.md
- 모든 plan.md 기능이 어떤 스프린트에 배치됐는지 추적 가능
- 스프린트 간 의존성 순서 준수
- 각 스프린트 종료 시 독립 동작 가능한 결과물

## 자기검증 체크리스트

계획 문서 완성 후 **문서 저장 전** 아래를 직접 실행한다:

### 1. 스펙 커버리지 확인
PRD(또는 요구사항)의 각 요구사항을 훑으며 계획 문서에 대응 항목이 있는지 확인.
대응 항목 없으면 해당 요구사항을 추가.

### 2. Placeholder 스캔
위의 "금지 표현" 목록으로 문서 전체를 검색. 발견 시 구체화.

### 3. 경로 일관성 확인
초반에 나열한 파일 경로가 나중 섹션에서도 같은 이름으로 쓰이는지 확인.
`TreatForm.pas`가 한 곳에서 `TreatmentForm.pas`로 다르게 쓰이면 버그.

### 4. 구현 가능성 테스트
"지금 Implementer에게 이 문서를 넘기면, 추가 질문 없이 구현할 수 있는가?"
→ 모른다면 → 그 부분을 보완

---

## 검증 실패 처리

체크리스트 항목 실패 시 수정 후 재검증. 재검증은 실패한 항목만.
문제가 없으면 즉시 다음 단계로 진행.
